# GameTree: создание и правка деревьев навыков

GameTree рисует одну большую карту навыков в стиле игровых деревьев прокачки. Карта
(проект) состоит из веток (trees), ветка из навыков (nodes). Навык открывается, когда
освоены все его `requires` и хотя бы один из `requiresAny`. Позиции на карте считаются
автоматически: чем длиннее цепочка требований, тем дальше навык от центра.

## Где лежат данные

Два режима работы, выбери по ситуации:

1. **В репозитории GameTree** (есть `data/projects/` и `scripts/build.mjs`):
   - `data/projects/<project-id>/project.json` описывает проект и порядок веток.
   - `data/projects/<project-id>/trees/<tree-id>.json` описывает ветку с навыками.
   - `data/projects.json` задаёт порядок проектов в меню.
   - После правок обязательно запусти `node scripts/validate.mjs`, потом `node scripts/build.mjs`.
2. **Без репозитория** (например, в обычном чате): собери один JSON-файл проекта в
   формате экспорта (ниже) и отдай его пользователю. Он загрузит его в приложении через
   меню ⋯ → «Импорт карты или прогресса» или меню проектов «Импорт проекта из JSON».

## Формат

`project.json` (в репозитории `trees` это список id файлов веток):

```json
{
  "schema": 1,
  "id": "backend",
  "title": "Backend-разработчик",
  "description": "Короткое описание карты",
  "center": { "title": "Backend" },
  "trees": ["java", "go"]
}
```

Ветка `trees/<id>.json`:

```json
{
  "id": "go",
  "title": "Go",
  "color": "#39c5cf",
  "description": "Одна-две фразы о ветке",
  "nodes": [
    {
      "id": "go.goroutines",
      "title": "Горутины и каналы",
      "abbr": "Chan",
      "description": "Что входит в навык, одной-двумя фразами.",
      "requires": ["go.structures", "go.errors"],
      "requiresAny": ["java.concurrency"],
      "keystone": true,
      "questions": [
        "Как работает select?",
        { "q": "Что будет при записи в закрытый канал?", "a": "panic: send on closed channel" },
        { "topic": "Sync", "items": ["Что такое WaitGroup?", "Чем Mutex отличается от RWMutex?"] }
      ],
      "resources": [{ "title": "A Tour of Go", "url": "https://go.dev/tour/" }]
    }
  ]
}
```

Экспортный формат (один файл) такой же, только `trees` содержит сами объекты веток.

Правила полей:
- `id` проекта и веток: строчный slug `[a-z0-9-]`. `id` навыка: `<tree-id>.<slug>`, уникален во всём проекте.
- `requires` и `requiresAny` ссылаются на id навыков из любой ветки проекта. Межветочные связи
  нужны и полезны (Spring Core требует Java ООП). Циклы запрещены.
- Навык без требований стартовый: он соединяется с центром карты. Таких в ветке 1–3.
- `keystone: true` для крупных узловых тем (1–3 на ветку): они крупнее и дают больше опыта.
- `abbr`: метка внутри кружка навыка на карте, 2–4 символа (`JVM`, `IoC`, `K8s`, `Chan`). Без эмодзи.
  Если не указать, приложение возьмёт аббревиатуру из названия.
- `questions`: вопросы для самопроверки. Элемент это строка, `{ "q", "a" }` с коротким ответом или
  подтема `{ "topic", "items": [...] }`, внутри которой снова вопросы и подтемы. Подтемы нужны, когда
  вопросов больше 6–8: в приложении двойной клик по навыку открывает его мини-карту в стиле XMind,
  где подтемы это ветки, а вопросы это листья. Держи глубину 1–2 уровня.
- `color` в формате `#rrggbb`, яркий, но не кислотный, отличный от соседних веток.
- `pos: {x, y}` появляется, если пользователь перетащил навык на карте. Не добавляй его сам.
- Не меняй `id` существующих навыков: по ним хранится прогресс пользователя.

## Как проектировать дерево

1. Выпиши 6–20 навыков ветки. Навык должен быть темой, которую можно изучить за 1–10 часов,
   а не отдельным вопросом. Мелкие факты уходят в `questions`.
2. Расставь требования по реальной логике обучения: сначала основы, потом то, что на них
   опирается. Держи 1–3 требования на навык, чтобы карта не превращалась в паутину.
3. Свяжи новую ветку с существующими: найди навыки, на которые она опирается
   (`grep -h '"id"' data/projects/<id>/trees/*.json`), и добавь их в `requires` стартовых навыков.
4. Добавь ветку в `trees` проекта рядом с родственными ветками: порядок веток задаёт их
   расположение по кругу, соседние ветки соединяются короче.
5. Пиши тексты на русском (если пользователь не просит иначе). Эмодзи нигде не используй: у навыка есть `abbr`.
6. Запусти `node scripts/validate.mjs` и исправь ошибки. Предупреждения о навыках без
   вопросов допустимы, но лучше добавить вопросы.
7. Запусти `node scripts/build.mjs`, чтобы обновить `dist/index.html`.

## Импорт mind map

Для XMind: `python3 scripts/xmind_import.py <файл.xmind> <project-id> "Название"`. Скрипт
создаёт черновик (первый уровень становится ветками, второй навыками, глубже вопросами и
подтемами) без зависимостей. После импорта пройди по шагам из «Как проектировать дерево»: объедини мелкие
ветки, добавь `requires`, описания, `abbr` и `keystone`.

## Ответы на вопросы

Если пользователь просит «добавь ответы», заполняй `a` кратко (2–5 предложений, без воды),
сохраняя текст `q` без изменений: по тексту вопроса хранится отметка «знаю». Строку-вопрос
можно превратить в `{ "q": "тот же текст", "a": "..." }`. Перенос вопроса в подтему тоже не
сбрасывает отметку, если текст не менялся.
