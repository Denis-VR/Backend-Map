# GameTree: создание и правка деревьев навыков

GameTree рисует карту навыков одним кругом. Карта (проект) состоит из тем (trees), тема из
разделов (nodes), раздел из вопросов. В центре название проекта, вокруг него кругами стоят
темы в порядке `trees` (по часовой стрелке), каждой теме принадлежит свой сектор: в нём от
темы наружу расходятся разделы, а от разделов вопросы и подтемы. Когда пользователь выбирает
тему, круг поворачивается к ней, и её ветка читается слева направо. Цвет вопроса показывает
сложность, красный «!» отмечает важные. Раздел открывается, когда освоены все его `requires` и хотя бы один из `requiresAny`.
Раскладка автоматическая, координат в данных нет.

## Где лежат данные

Два режима работы, выбери по ситуации:

1. **В репозитории GameTree** (есть `data/projects/` и `scripts/build.mjs`):
   - `data/projects/<project-id>/project.json` описывает проект и порядок тем по кругу.
   - `data/projects/<project-id>/trees/<tree-id>.json` описывает тему с разделами.
   - `data/projects.json` задаёт порядок проектов в меню.
   - После правок обязательно запусти `node scripts/validate.mjs`, потом `node scripts/build.mjs`.
2. **Без репозитория** (например, в обычном чате): собери один JSON-файл проекта в
   формате экспорта (ниже) и отдай его пользователю. Он загрузит его в приложении через
   меню ⋯ → «Импорт карты или прогресса» или меню проектов «Импорт проекта из JSON».

## Формат

`project.json` (в репозитории `trees` это список id файлов тем, в порядке по кругу):

```json
{
  "schema": 2,
  "id": "backend",
  "title": "Backend-разработчик",
  "description": "Короткое описание карты",
  "center": { "title": "Backend Stack" },
  "trees": ["java-core", "go"]
}
```

Тема `trees/<id>.json`:

```json
{
  "id": "go",
  "title": "Go",
  "color": "#2ea8e6",
  "description": "Одна-две фразы о теме",
  "nodes": [
    {
      "id": "go.concurrency",
      "title": "Concurrency",
      "abbr": "Chan",
      "level": 2,
      "description": "Что входит в раздел, одной-двумя фразами.",
      "requires": ["go.structures"],
      "requiresAny": ["java.concurrency"],
      "questions": [
        "Как работает select?",
        { "q": "Что будет при записи в закрытый канал?", "a": "panic: send on closed channel", "level": 2, "important": true },
        { "topic": "Sync", "items": ["Что такое WaitGroup?", { "q": "Чем Mutex отличается от RWMutex?", "level": 3 }] }
      ],
      "resources": [{ "title": "A Tour of Go", "url": "https://go.dev/tour/" }]
    }
  ]
}
```

Экспортный формат (один файл) такой же, только `trees` содержит сами объекты тем.

Правила полей:
- `id` проекта и тем: строчный slug `[a-z0-9-]`. `id` раздела: `<префикс>.<slug>`, уникален во всём проекте.
- `requires` и `requiresAny` ссылаются на id разделов из любой темы проекта. Связи между темами
  нужны и полезны (Spring Core требует Java ООП). Циклы запрещены. На карте связи видны пунктиром,
  когда раздел выбран.
- `level`: сложность от 1 до 4, цвета как в XMind: 1 базовый (зелёный `#7fd492`), 2 средний
  (жёлтый `#f2cf3a`), 3 сложный (оранжевый `#ff7a1a`), 4 эксперт (фиолетовый `#c37ad3`). Ставится
  у темы, раздела, подтемы или вопроса; вопрос без своего `level` берёт его у подтемы, раздела или темы.
  Цвет темы обычно совпадает с цветом её сложности.
- `important: true` у вопроса или подтемы: красный «!», отдельный фильтр и режим повторения «Важные».
- `abbr`: короткая метка раздела в панели и поиске, 2–4 символа (`JVM`, `IoC`, `K8s`, `Chan`). Без эмодзи.
  Если не указать, приложение возьмёт аббревиатуру из названия.
- `questions`: вопросы для самопроверки. Элемент это строка, `{ "q", "a", "level", "important" }` или
  подтема `{ "topic", "items": [...] }`, внутри которой снова вопросы и подтемы. Подтемы рисуются на
  карте как маленькие плашки со своими вопросами справа. Держи глубину 1–3 уровня.
- `color` темы в формате `#rrggbb`, яркий, но не кислотный.
- Не меняй `id` существующих разделов: по ним хранится прогресс пользователя.

## Как проектировать дерево

1. Выпиши 3–9 разделов темы. Раздел это кусок темы, который можно изучить за 1–10 часов,
   а не отдельный вопрос. Мелкие факты уходят в `questions`.
2. Расставь сложность: `level` у темы и разделов, у отдельных вопросов, если они заметно
   сложнее соседей. Отметь `important` вопросы, которые чаще всего спрашивают.
3. Расставь требования по реальной логике обучения: сначала основы, потом то, что на них
   опирается. Держи 1–3 требования на раздел, чтобы не было паутины.
4. Свяжи новую тему с существующими: найди разделы, на которые она опирается
   (`grep -h '"id"' data/projects/<id>/trees/*.json`), и добавь их в `requires`.
5. Поставь тему в `trees` проекта туда, где её изучают по порядку: круг читается по часовой стрелке от верха.
6. Пиши тексты на русском (если пользователь не просит иначе). Эмодзи нигде не используй.
7. Запусти `node scripts/validate.mjs` и исправь ошибки. Предупреждения о разделах без
   вопросов допустимы, но лучше добавить вопросы.
8. Запусти `node scripts/build.mjs`, чтобы обновить `dist/index.html`.

## Импорт mind map

Для XMind: `python3 scripts/xmind_import.py <файл.xmind> <project-id> "Название"`. Скрипт
повторяет карту: первый уровень становится темами круга, второй разделами, глубже
вопросами и подтемами. Цвета текста и линий превращаются в `level` (зелёный 1, жёлтый 2,
оранжевый 3, фиолетовый 4), маркер «!» или приоритет 1 в `important`, заметки в ответы.
Вопросы, висящие прямо на теме, собираются в раздел «Общие вопросы». После импорта добавь
`requires`, описания и `abbr`.

## Ответы на вопросы

Если пользователь просит «добавь ответы», заполняй `a` кратко (2–5 предложений, без воды),
сохраняя текст `q` без изменений: по тексту вопроса хранится отметка «знаю». Строку-вопрос
можно превратить в `{ "q": "тот же текст", "a": "..." }`. Перенос вопроса в подтему тоже не
сбрасывает отметку, если текст не менялся.
